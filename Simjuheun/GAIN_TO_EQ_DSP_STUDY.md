# 처음 만든 오디오 플러그인: Gain에서 Biquad EQ까지

> JUCE 플러그인을 처음 만들면서 Gain, Smoothing, Dry/Wet, Delay를 거쳐
> Bell, Low/High-pass, Low/High-shelf, Notch까지 구현한 과정을 정리했다.
> 수식을 외우는 것보다 **사용자가 입력한 값이 어떻게 샘플 계산으로 이어지는지**를
> 이해하는 데 초점을 맞춘 글이다.

---

## 1. 결국 플러그인은 샘플을 받아서 다른 샘플을 돌려준다

DAW에서 재생되는 오디오는 아주 많은 숫자의 연속이다. 각각의 숫자는 특정 순간의
공기 진동 크기, 즉 진폭을 나타낸다.

```text
입력 샘플:  [ 1.0, 0.5, -0.5, -1.0, ... ]
플러그인:   각 샘플을 계산
출력 샘플:  [ 0.5, 0.25, -0.25, -0.5, ... ]
```

플러그인이 음원 파일을 직접 열어 읽는 것은 아니다. DAW가 재생 중인 오디오를 작은
블록으로 나누어 플러그인의 `processBlock()`에 전달한다.

```text
음원 파일 또는 마이크
        ↓
       DAW
        ↓ 오디오 버퍼
processBlock()
        ↓ 처리된 버퍼
       DAW
        ↓
    스피커 또는 다음 플러그인
```

### JUCE의 역할

JUCE는 이 과정에서 DAW와 플러그인 사이를 연결해 준다.

- Logic이 보내는 Audio Unit 버퍼 받기
- 다른 DAW가 보내는 VST3 버퍼 받기
- Sample Rate, 채널 수, Buffer Size 전달
- 파라미터 자동화와 프로젝트 저장·복원
- 플러그인 UI 창 생성

덕분에 DSP 코드는 AU와 VST3의 차이를 직접 처리하지 않고, JUCE가 제공한 버퍼의
샘플을 계산하는 데 집중할 수 있다.

### Processor와 Editor

```text
PluginProcessor → 실제 오디오 처리와 파라미터 관리
PluginEditor    → 노브, 메뉴, 그래프 같은 화면
```

Editor의 노브가 소리를 직접 바꾸는 것은 아니다. 노브가 파라미터 값을 바꾸면
Processor가 그 값을 읽고 DSP 계산에 사용한다.

### CMake의 역할

JUCE가 플러그인 제작 재료라면 CMake는 조립 설명서에 가깝다.

```text
어떤 소스 파일을 컴파일할지
어떤 JUCE 모듈을 사용할지
AU, VST3, Standalone 중 무엇을 만들지
제품명과 제조사 코드를 무엇으로 할지
```

CMake 프로젝트이므로 코드는 VS Code, Xcode 등 원하는 편집기에서 수정할 수 있다.
빌드 방법과 프로젝트 정의가 특정 편집기에 묶이지 않는 것이 장점이다.

## 2. 첫 번째 DSP: Gain

Gain은 가장 단순하지만 DSP의 전체 흐름을 이해하기에 가장 좋은 출발점이었다.

```text
출력 샘플 = 입력 샘플 × Gain
```

입력 샘플을 절반으로 줄이고 싶다면 모든 샘플에 `0.5`를 곱하면 된다.

```text
입력: [ 1.0, 0.5, -0.5, -1.0 ]
계산: 각 샘플 × 0.5
출력: [ 0.5, 0.25, -0.25, -0.5 ]
```

### dB는 샘플에 직접 곱할 수 없다

사용자는 Gain을 dB로 조절하지만 샘플 계산에는 선형 배수가 필요하다.

```text
선형 Gain = 10^(dB / 20)
```

대표적인 값은 다음과 같다.

```text
  0 dB      → 1.0배
 +6.0206 dB → 2.0배
 -6.0206 dB → 0.5배
-∞ dB       → 0배
```

`-6 dB가 약 절반`이라는 말은 오디오 샘플의 진폭이 약 0.5배가 된다는 뜻이다.

### 다른 분야의 비유: 화면 밝기

사진의 모든 픽셀 밝기에 `0.5`를 곱하면 사진 전체가 어두워진다. Gain도 오디오의 모든
샘플에 같은 배수를 곱한다는 점에서 비슷하다. 픽셀 대신 시간 순서의 샘플을 처리할 뿐이다.

---

## 3. Gain을 갑자기 바꾸면 왜 Smoothing이 필요한가

Gain 노브를 움직여 선형 Gain이 한 샘플 사이에 `1.0`에서 `0.2`로 갑자기 바뀌면 파형이
불연속적으로 꺾인다. 이 급격한 변화에는 원래 음원에 없던 넓은 고주파 성분이 생기며,
클릭이나 지퍼 노이즈로 들릴 수 있다.

```text
즉시 변경: 1.0 → 0.2
Smoothing: 1.0 → 0.9 → 0.8 → ... → 0.2
```

GainLab에서는 약 20 ms 동안 이전 값에서 새 값으로 선형 이동하도록 만들었다.

### Smoother가 지역변수이면 안 되는 이유

DAW는 오디오를 여러 블록으로 나누어 반복해서 `processBlock()`을 호출한다. Smoother를
함수 안의 지역변수로 만들면 블록이 끝날 때 진행 상태가 사라진다.

```text
블록 1: 1.0 → 0.8까지 이동
블록 2: 0.8부터 계속 이동해야 함
```

따라서 Smoother는 Processor의 멤버로 두어 블록이 바뀌어도 현재 값을 기억하게 했다.

### 다른 분야의 비유: 자동차의 가속

가속 페달 목표가 바뀌었다고 자동차 속도가 즉시 20 km/h에서 100 km/h로 순간이동하지
않는다. 일정 시간에 걸쳐 속도가 변한다. Smoothing도 파라미터의 목표값까지 이동하는
짧은 가속 구간이라고 생각할 수 있다.

## 4. Dry/Wet과 Delay에서 배운 상태와 시간

### Dry/Wet

Dry는 원본, Wet은 효과 처리된 소리다.

```text
출력 = Dry × (1 - Mix) + Wet × Mix
```

```text
Mix 0%   → 원본만
Mix 50%  → 원본과 효과를 절반씩
Mix 100% → 효과음만
```

Send/Aux 방식에서는 원본 트랙이 이미 Dry를 재생하므로, Send에 걸린 효과는 보통
`100% Wet`으로 사용한다.

### Delay

Delay는 현재 소리를 즉시 계산해서 끝내지 않고, 원형 버퍼에 저장했다가 일정 시간 후
다시 꺼낸다.

```text
Delay Time → 얼마나 과거의 샘플을 읽을지
Feedback   → 읽은 소리를 얼마나 다시 버퍼에 넣을지
Dry/Wet    → 원본과 지연음을 얼마나 섞을지
```

Delay Time을 ms에서 샘플 개수로 바꾸려면 Sample Rate가 필요하다.

```text
Delay Samples = Delay ms × Sample Rate / 1000
```

예를 들어 48 kHz 프로젝트에서 250 ms는 `12,000 samples`이다.

Delay 버퍼도 Smoother와 마찬가지로 블록이 바뀌어도 과거 샘플을 기억해야 하므로
Processor의 멤버로 유지한다. 오디오 처리 중 메모리 할당을 피하기 위해 최대 크기의
버퍼는 `prepareToPlay()`에서 미리 만든다.

## 5. EQ는 특정 주파수 영역의 크기를 바꾸는 도구다

Gain이 모든 샘플을 같은 비율로 바꾼다면 EQ는 주파수에 따라 다른 비율을 적용한다.

```text
Gain → 전체 주파수를 함께 키우거나 줄임
EQ   → 선택한 주파수 영역만 키우거나 줄임
```

실제 음악 파형은 일정한 사인파처럼 보이지 않는다. 그렇지만 복잡한 파형도 여러
주파수의 사인파가 순간순간 합쳐진 것으로 해석할 수 있다.

```text
복잡한 음원
= 낮은 주파수 성분
+ 중간 주파수 성분
+ 높은 주파수 성분
+ 계속 변하는 수많은 성분
```

필터가 매 샘플마다 FFT로 주파수를 분석하는 것은 아니다. 현재와 과거의 샘플을 정해진
가중치로 계속 계산하면 어떤 진동 패턴은 강화되고 어떤 패턴은 상쇄된다. 그 결과
주파수마다 다른 Gain이 적용된다.

## 6. FIR과 IIR

필터가 과거를 사용하는 방식은 크게 FIR과 IIR로 나눌 수 있다.

```text
FIR → 현재 입력 + 과거 입력들
IIR → 현재·과거 입력 + 과거 출력
```

### FIR

```text
현재 출력 = 현재 입력 × 0.5 + 이전 입력 × 0.5
```

사용할 과거 입력의 개수를 Tap 수라고 한다. Tap이 많으면 정교한 필터를 만들 수 있지만
계산량과 지연이 늘어난다. 선형 위상이 필요한 마스터링 EQ나 크로스오버 등에서 유용하다.

### IIR

```text
현재 출력 = 현재 입력의 일부 + 이전 출력의 일부
```

이전 출력 안에는 그보다 더 오래된 입력의 영향도 이미 들어 있다. 적은 메모리와 계산으로
긴 반응을 만들 수 있어 실시간 파라메트릭 EQ에 많이 사용된다.

### 다른 분야의 비유: 이동 평균과 누적 평균

- FIR은 최근 며칠의 실제 기온만 모아 평균을 내는 방식과 비슷하다.
- IIR은 오늘의 기온과 어제 계산했던 평균을 다시 섞는 방식과 비슷하다.

IIR은 이전 결과를 계속 사용하므로 적은 값만 보관해도 오래된 정보가 간접적으로 남는다.

## 7. Biquad: EQ의 작은 기본 블록

Biquad는 과거 입력 두 개와 과거 출력 두 개를 사용하는 2차 IIR 필터다.

```text
y[n] = b₀x[n]
     + b₁x[n-1]
     + b₂x[n-2]
     - a₁y[n-1]
     - a₂y[n-2]
```

여기서 입력·출력 샘플과 계수를 구분해야 한다.

```text
x[n], x[n-1], x[n-2] → 실제 입력 샘플
y[n-1], y[n-2]       → 실제 과거 출력 샘플
b₀, b₁, b₂, a₁, a₂   → 샘플에 곱하는 가중치
```

### 다섯 계수의 역할

```text
b₀ → 현재 입력의 가중치
b₁ → 한 샘플 전 입력의 가중치
b₂ → 두 샘플 전 입력의 가중치
a₁ → 한 샘플 전 출력을 되먹이는 가중치
a₂ → 두 샘플 전 출력을 되먹이는 가중치
```

`b` 계수들은 입력들이 서로 강화되거나 상쇄되는 모양, 즉 Zero 쪽 성질을 만든다.
`a` 계수들은 과거 출력을 다시 사용해 기억, 감쇠, 공진 같은 Pole 쪽 성질을 만든다.

개별 계수를 `b₀=Gain`, `a₁=Q`처럼 해석하면 안 된다. 다섯 값이 함께 하나의 필터 모양을
만든다.

### 왜 다섯 개인가

원래 식에는 `a₀`까지 여섯 계수가 있다.

```text
a₀, a₁, a₂, b₀, b₁, b₂
```

모든 항을 `a₀`로 나누면 `a₀=1`로 만들 수 있어 저장할 필요가 없다. 그래서 정규화된
Biquad는 다섯 계수만 저장한다.

2차 필터는 두 개의 Pole과 두 개의 Zero를 만들 수 있다. Frequency, Gain, Q를 조절하는
Bell과 공진이 있는 Pass 필터를 만들 수 있는 가장 작은 실용적인 단위다.

## 8. Sample Rate가 계수 계산에 필요한 이유

사용자가 입력하는 Frequency는 Hz, 즉 1초에 몇 번 반복되는지를 의미한다. 하지만 필터는
초가 아니라 샘플 순서로 계산한다.

```text
1 kHz @ 48 kHz → 한 주기에 약 48 samples
1 kHz @ 96 kHz → 한 주기에 약 96 samples
```

따라서 Hz를 샘플 기준 각도로 바꾼다.

```text
ω = 2π × Frequency / Sample Rate
```

48 kHz용으로 계산한 1 kHz 계수를 96 kHz에서 그대로 쓰면 필터 위치는 약 2 kHz로
이동한다. 그래서 DAW가 `prepareToPlay()`로 알려 준 프로젝트 Sample Rate를 저장했다가
계수 계산에 사용한다.

Buffer Size는 한 번에 처리할 샘플 개수일 뿐 필터의 주파수 모양을 결정하지 않는다.
채널 수 역시 계수에는 영향을 주지 않는다. 좌우 채널은 같은 계수를 사용하되, 서로 다른
과거 샘플을 기억하기 위해 필터 상태만 따로 가진다.

---

## 9. 사용자 파라미터와 계수는 1:1로 대응하지 않는다

사용자는 필터 모양을 이해하기 쉬운 값으로 표현한다.

```text
Bell  → Frequency, Gain, Q
Pass  → Frequency, Q
Shelf → Frequency, Gain, Slope
Notch → Frequency, Q
```

이 값들은 각각 특정 계수 하나에 대응하지 않는다. 선택한 필터 공식에 모든 파라미터를
함께 넣어 다섯 계수를 동시에 계산한다.

```text
필터 종류 + 사용자 파라미터 + Sample Rate
                  ↓
          필터 종류별 공식
                  ↓
          b₀, b₁, b₂, a₁, a₂
```

### 다른 분야의 비유: 사진 필터

사진 편집기에서 Blur Radius와 Strength를 설정한다고 해서 Radius가 특정 픽셀 가중치
하나에만 대응하는 것은 아니다. 두 설정을 함께 사용해 주변 픽셀에 곱할 여러 가중치를
만든다. 오디오 필터도 Frequency, Gain, Q를 받아 시간 방향 샘플에 곱할 가중치들을 만든다.

파라미터는 사람이 원하는 결과를 말하는 언어이고, 계수는 컴퓨터가 그 결과를 만들기
위해 사용하는 계산 언어다.

## 10. Pole, Zero와 공진을 말로 이해하기

Pole과 Zero는 음원 안에 들어 있는 물체가 아니라 필터 계수가 만들어내는 수학적 성질이다.

- Zero가 특정 주파수 가까이에 있으면 입력들이 서로 상쇄되어 그 주파수가 줄어든다.
- Pole이 특정 주파수 가까이에 있으면 과거 출력의 진동이 현재 입력과 반복해서 겹쳐
  그 주파수가 강화되거나 오래 남는다.

공진은 특정 주파수의 진동이 필터 내부 피드백과 같은 박자로 겹쳐 커지는 현상이다.
그네가 움직이는 박자에 맞춰 계속 밀면 작은 힘도 누적되는 것과 비슷하다.

```text
주변 주파수까지 변화하는 범위 → 대역폭
특정 진동이 누적되어 솟는 현상 → 공진
대역폭과 공진 지속성을 조절    → Q
```

## 11. 구현한 필터들

### 11.1 Bell

Bell은 중심 주파수 주변을 종 모양으로 올리거나 내린다.

```text
Frequency → 중심 위치
Gain      → 봉우리 높이 또는 골 깊이
Q         → 폭
```

```text
1 kHz / +6 dB / Q 1  → 1 kHz 주변을 넓게 +6 dB
1 kHz / +6 dB / Q 10 → 1 kHz 근처만 좁게 +6 dB
```

Bell 공식에서는 Gain을 다음 값으로 바꿔 사용한다.

```text
A = 10^(Gain dB / 40)
```

일반 Gain의 `/20`과 다른 이유는 Bell 공식에서 `A`와 `1/A`를 분자와 분모에 대칭적으로
사용하며, 중심에서 결과적으로 `A²`의 크기 변화가 만들어지기 때문이다.

Bell은 일반적인 믹싱에서 가장 범용적인 도구다. 문제 주파수를 조금 줄일 때도, 원하는
음색 영역을 넓게 강조할 때도 사용할 수 있다.

### 11.2 Low-pass와 High-pass

```text
Low-pass  → 낮은 주파수 통과, 높은 주파수 감쇠
High-pass → 높은 주파수 통과, 낮은 주파수 감쇠
```

믹싱 UI에서는 다음 이름도 자주 사용한다.

```text
High Cut = Low-pass
Low Cut  = High-pass
```

Pass 필터에는 일반적으로 Gain이 없다. 한쪽 대역을 0 dB로 통과시키고 반대쪽을 계속
감쇠하는 것이 목적이기 때문이다.

#### Q와 0.707

2차 Pass 필터에서 Q가 높으면 Cutoff 근처의 진동이 피드백에 누적되어 봉우리가 생긴다.

공진 피크가 0 dB 위로 솟지 않는 조건을 계산하면 다음 경계가 나온다.

```text
Q² ≤ 1/2
Q  ≤ √(1/2)
Q  ≤ 약 0.707
```

```text
Q < 0.707 → 공진은 없지만 더 일찍 완만하게 감소
Q = 0.707 → 공진 없이 통과 영역이 가장 평평함
Q > 0.707 → Cutoff 주변에 공진 피크 발생
```

Q가 약 0.707인 응답을 Butterworth라고 한다. 이때 Cutoff의 진폭은 0.707배이고,
dB로는 약 `-3.01 dB`다.

`1 kHz, Q=1`인 Low-pass는 약 700 Hz 부근에서 `+1.25 dB` 정도 솟았다가 1 kHz에서
0 dB를 지나 감쇠한다. 이것은 오류가 아니라 Q가 만든 공진이다.

### 11.3 Low Shelf와 High Shelf

Shelf는 한쪽 주파수 영역 전체를 설정 Gain으로 이동시킨다.

```text
Low Shelf  → 낮은 주파수 영역을 올리거나 내림
High Shelf → 높은 주파수 영역을 올리거나 내림
```

```text
Frequency → 두 평평한 Gain 영역의 중간 위치
Gain      → 한쪽 영역이 도달할 높이
Slope     → 두 영역을 얼마나 급하게 연결할지
```

`Low Shelf / 1 kHz / +6 dB`라면:

```text
낮은 주파수 → +6 dB
1 kHz       → +3 dB
높은 주파수 →  0 dB
```

여기서 두 Gain은 Gain 노브가 두 개라는 뜻이 아니다. 변화하지 않는 `0 dB` 영역과
사용자가 설정한 `+6 dB` 영역을 말한다. Shelf 전환에는 정확한 시작과 끝을 정하기
어려우므로 두 높이의 중간을 Frequency로 사용한다.

Slope가 1이면 가장 급하면서 단조로운 표준 Shelf가 되고, 값이 작아지면 전환 구간이
더 넓고 완만해진다.

Shelf는 Pass와 다르다. Pass는 한쪽을 계속 감쇠해 제거하지만 Shelf는 설정 Gain에
도달하면 다시 평평해진다.

### 11.4 Notch

Notch는 Frequency에서 입력들이 정확히 상쇄되도록 Zero를 배치한다.

```text
Frequency → 제거할 중심 주파수
Q         → 제거되는 홈의 폭
Gain      → 사용하지 않음
```

Notch의 입력 쪽 핵심 계수는 다음 형태다.

```text
b₀ = 1
b₁ = -2cos(ω)
b₂ = 1
```

선택한 Frequency에서 현재 입력과 과거 입력들이 반대 방향으로 겹쳐 결과가 0에
가까워진다.

```text
Notch 1 kHz, Q 1
100 Hz  ≈ -0.04 dB
1 kHz   ≈ -144.8 dB
10 kHz  ≈ -0.03 dB
```

이론적으로 중심은 정확히 0이지만 컴퓨터의 부동소수점 정밀도 때문에 유한한 매우 작은
값으로 측정된다.

실제 믹싱에서는 대부분 Bell Cut으로 충분하다. Notch는 50/60 Hz 전기 Hum, 일정한
Whine, 심한 고정 공진처럼 위치가 변하지 않는 좁은 문제를 완전히 제거할 때 사용한다.

```text
일반적인 음색 보정 → Bell Cut
심한 고정 톤 제거  → Notch
시간에 따라 이동  → Dynamic EQ
```

## 12. 회사마다 EQ 소리가 다른 이유

완전히 같은 계수와 같은 계산식을 사용하면 회사가 달라도 결과는 사실상 같다. 제품마다
차이가 생기는 지점은 더 넓다.

- Frequency, Gain, Q를 내부 값으로 매핑하는 방식
- Gain에 따라 Q가 변하는 Constant-Q 또는 Proportional-Q 설계
- 12/24/48 dB per octave 같은 필터 차수와 연결 방식
- 높은 주파수에서 디지털 주파수 휨을 보정하는 방식
- 파라미터 Smoothing과 계수 전환 방식
- Oversampling
- 아날로그 회로의 포화, 노이즈, 트랜스포머 모델링
- 여러 밴드가 상호작용하는 방식

그래서 같은 `1 kHz, +6 dB, Q 1`이라도 제품에 따라 곡선과 시간 반응이 조금 다를 수
있다.

## 13. 응답 그래프는 스펙트럼 분석기가 아니다

EqLab의 그래프는 들어오는 음원에 어떤 주파수가 있는지 보여 주는 Analyzer가 아니다.
현재 다섯 계수를 여러 주파수에 대입해 **이 필터가 각 주파수를 몇 dB 바꿀지** 계산한
주파수 응답이다.

```text
Analyzer       → 현재 음원에 무엇이 들어 있는가
Response Graph → 현재 필터가 무엇을 바꾸는가
```

그래프와 오디오 DSP가 같은 계수를 사용하므로 노브를 움직였을 때 보이는 곡선과 실제
필터 동작이 일치한다.

## 14. DSP를 DAW 없이 테스트한 방법

플러그인을 매번 Logic에서 열어 귀로만 확인하면 작은 실수를 찾기 어렵다. DSP 클래스를
JUCE와 분리해 작은 실행 파일에서 테스트했다.

### Gain 테스트

```text
입력: [ 1, 0.5, -0.5, -1 ]
Gain: -6.0206 dB → 0.5배
기대 출력: [ 0.5, 0.25, -0.25, -0.5 ]
```

### EQ 테스트

```text
Bell 1 kHz, +6 dB → 실제 1 kHz가 +6 dB인지 측정
Low-pass 1 kHz    → 100 Hz 통과, 10 kHz 감쇠 확인
High-pass 1 kHz   → 100 Hz 감쇠, 10 kHz 통과 확인
Low Shelf +6 dB   → 저역 +6 dB, 중심 +3 dB, 고역 0 dB 확인
High Shelf +6 dB  → 저역 0 dB, 중심 +3 dB, 고역 +6 dB 확인
Notch 1 kHz       → 1 kHz가 사실상 제거되는지 확인
```

테스트가 통과한 뒤 AU와 VST3 전체를 빌드하고 macOS의 `auval`로 AU 형식, 파라미터,
모노·스테레오 처리, 여러 Sample Rate의 렌더링을 검증했다.

## 17. 다시 볼 때 기억할 핵심 문장

1. 플러그인은 DAW가 준 샘플 배열을 받아 계산하고 같은 버퍼에 결과를 돌려준다.
2. dB는 사용자 단위이고, 샘플에는 `10^(dB/20)`으로 바꾼 선형 값을 곱한다.
3. 상태이거나 시간에 걸쳐 진행되는 DSP는 `processBlock()`의 지역변수가 아니라
   Processor 멤버로 유지한다.
4. Sample Rate는 Hz를 샘플 기준 위치나 개수로 바꾸기 위해 필요하다.
5. Biquad의 다섯 계수는 샘플 자체가 아니라 현재·과거 입력과 과거 출력에 곱할 가중치다.
6. 사용자 파라미터와 계수는 1:1 대응하지 않는다. 모든 파라미터가 함께 다섯 계수를
   결정한다.
7. Bell은 범용적인 증감, Pass는 한쪽 제거, Shelf는 한쪽 영역 이동, Notch는 고정된
   좁은 문제 제거에 적합하다.
8. Q는 단순한 폭뿐 아니라 피드백의 감쇠와 공진 지속성에도 관계한다.
9. 그래프는 실제 DSP 계수로 계산해야 화면과 소리가 일치한다.
10. 귀로 듣기 전에 알려진 입력과 기대 출력으로 DSP를 자동 테스트할 수 있다.

## 마무리

처음에는 플러그인이 음원 파일을 읽고 주파수를 분석한 다음 효과를 적용할 것이라고
생각했다. 실제 핵심은 훨씬 작았다.

```text
현재 샘플을 받고
과거 상태를 참고하고
정해진 가중치로 계산하고
다음 샘플을 위해 상태를 기억한다.
```

Gain은 한 개의 선형 가중치였고, Biquad EQ는 다섯 개의 가중치였다. 사용자에게 보이는
Frequency, Gain, Q, Slope는 이 가중치를 직접 노출하지 않고 원하는 소리의 모양을
설명하게 해 주는 인터페이스였다.

다음 단계에서는 Envelope로 현재 소리의 크기를 추적하고, 그 결과로 Gain을 자동 조절하는
Compressor, De-esser, Dynamic EQ의 흐름을 공부할 수 있다. 지금까지 만든 정적 필터가
“항상 같은 설정으로 처리”했다면, Envelope 이후의 DSP는 “입력 신호의 상태에 따라
설정이 계속 변하는 처리”가 된다.
